# 2.0 人球识别：阶段总结与后续规划

- **项目定位**：独立基础实验 / 项目 A
- **对应论文方向**：基于视频时序特征的篮球动作识别与事件定位
- **与 2.1 的关系**：2.1 继承 2.0 的可复现实验资产，但不覆盖 2.0 的原始材料，也不把 2.0 的架构设为后续创新项目的硬约束。
- **事实来源**：[人球识别 2.0 实验总结](../传输/人球识别2.0_实验总结.docx)、[行为识别论文精读与提升路线总结](../行为识别论文精读与提升路线总结.docx)及项目现有代码、日志和实验记录。

## 一、阶段目标

2.0 的目标是建立从人球检测到篮球动作识别的可运行基础链路，比较不同检测与动作模型，验证球特征、时序建模和事件解码是否真正有贡献，并为后续独立测试和论文写作保留可复现实验资产。

## 二、已经完成的工作

### 2.0 检测阶段

- 建立人员与篮球两类目标检测流程，人员类别包含球员和裁判；
- 完成类别权重与含球帧过采样对照，确定 `[1,2] + 2x` 过采样作为 2.0 的定稿训练配置；
- 完成七架构对照，现有总结中 YOLO26s 作为综合选型，记录了 person、ball、mAP50-95、参数量和计算量等指标；
- 保留标准 val 与 val35 两种难度口径，并明确两种口径的分数不能直接混排；
- 记录了 RTDETR-l 的内存崩溃、workers 调整和重启过程，保留失败过程作为工程证据。

### 二阶段动作识别

- 建立 YOLO 检测、跟踪、球员图块提取、R(2+1)D-18 / MViT v2 S 分类、时序解码和评测链路；
- 比较单帧、短时序和不同分类头，形成以时序特征为核心的基线；
- 验证球运动学与人球关系特征的重要性：已有记录显示，移除球特征时帧级 Macro-F1 从 0.594 降至 0.302，`shoot` / `pass` 识别明显失效；这一结果作为已有实验记录使用，不在本文件中重新解释为新实验；
- 记录 clip 级分类与完整视频事件定位之间的差距，确认问题集中在时序解码、事件边界和长尾类别，而不只是检测器架构；
- 保留 argmax、峰值检测、时间 NMS、滞回解码、语义门控和 BallFused 等对照及负结果。

## 三、阶段结论

1. YOLO 检测是动作识别的必要输入，但单独更换检测器不能解决动作判别问题；
2. `shoot` 与 `pass` 需要动作前后连续帧和球运动信息，单帧外观不足以稳定区分；
3. 球特征对动作识别具有实质作用，但训练时 GT 球轨迹与部署时检测球轨迹之间存在输入差异；
4. R(2+1)D、MViT 和轻量时序头都应保留为可复现基线，是否引入更大模型要由独立实验决定；
5. 当前最大风险是评测可信度：验证视频数量有限，配置选择与评估存在复用风险，稀有类别事件数不足以支撑很小的性能差异；
6. 2.0 适合整理为一篇基础动作识别与事件定位论文，但投稿前必须补齐独立测试、统一评测、多随机种子和事件级统计。

## 四、后续机器执行规划

### 阶段 A：冻结并复核 2.0 基线

- 固定数据划分、输入预处理、权重、随机种子和评测脚本版本；
- 建立 2.0 baseline manifest，列出每个模型、配置、checkpoint、日志和输出位置；
- 复核数据泄漏、视频划分、时间戳、类别映射和评测匹配规则；
- 对现有成功与失败结果分别归档，禁止用新结果覆盖旧日志。

### 阶段 B：重装评测协议

- 同时报告 clip/frame 级和事件级指标；
- 报告各类别 Precision、Recall、F1、Macro-F1，以及事件容差或 tIoU 指标；
- 对稀有类别标出事件数量和不确定性，不把小于测量噪声的差异写成改进；
- 在未参与配置选择的独立比赛上做最终测试；
- 关键对照采用多随机种子，并保留完整日志和配置。

### 阶段 C：先做低风险解码实验

- 在现有模型输出上比较逐类概率峰值、时间 NMS、滞回和事件合并；
- 评估球轨迹条件化放在分类端、解码端和两者结合时的差异；
- 先用可复用输出验证解码假设，再决定是否改动网络结构。

### 阶段 D：验证真实球输入鲁棒性

- 对比 GT 球、检测球、漏检插值、轨迹抖动和不同质量等级；
- 分析 BallFused 在真实检测输入下的收益与失效类别；
- 只有输入差异得到控制后，才决定是否增加人球交互或姿态分支。

### 阶段 E：形成论文证据链

论文需要回答：现有方法在哪些动作和场景失败，球与时序信息为何必要，新的解码或交互机制为何有效，以及在独立比赛和不完美检测输入下是否仍然成立。所有结论必须由同条件对照和可追溯日志支持。

## 五、需要项目负责人完成的人工输入

这些事项不属于训练机执行步骤：

- 录制或提供不同比赛、不同机位的完整视频；
- 封存一场永不参与配置选择的独立测试比赛；
- 补充 `pass`、`defense` 等稀有行为的人工标注；
- 对疑似异常标注、动作边界和球场标定点进行人工确认；
- 需要时完成双人标注和一致性复核。

训练机只能根据人工输入开展自动分析、训练、推理、评测和报告整理，不得代做上述事项。

## 六、阶段出口标准

满足以下条件后，2.0 才具备作为基础论文结果提交的条件：

- 基线、数据划分和评测脚本可复现；
- 独立测试集与验证集职责清晰；
- 关键结论有多随机种子或不确定性说明；
- GT 输入与部署输入分开报告；
- 事件级结果、失败样例和负结果均已归档；
- 论文贡献不依赖未经验证的更大模型堆叠。
